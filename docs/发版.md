# 发版与 Release

## 为什么需要流程

Android 只认 `versionCode` 判断是不是升级。数字不涨，覆盖安装虽然能装进去，
但系统层面不认为是新版本；涨了但包是旧的，用户会以为「更了没变化」。
所以版本号跟着包走，别手改。

## 一次发版

```
python build_apk.py --bump        # 版本号 +1，出包（约 7 分钟）
python tools/smoke.py --install   # 装到真机过一遍，确认资源缺失 0 条
git add -A
git commit -m "发版 1.0.3：<这次改了什么>"
git tag v1.0.3
git push origin main --tags
```

版本号存在 `version.txt`，一行数字。`--bump` 会先加一再打包，
`versionName` 自动变成 `1.0.<versionCode>`。

## 传 Release

网页上传也行，156MB 建议用命令行，断了可以重试：

```
gh release create v1.0.3 行测红卷.apk \
  --title "行测红卷 v1.0.3" \
  --notes-file docs/release-notes.md
```

GitHub 单文件上限 2GB，156MB 没问题；Release 附件不进 git 历史，仓库不会被撑大。

## Release 正文写什么

`docs/release-notes.md` 是模板，每次改「这次改了什么」那一段即可。
安装说明和签名指纹基本不用动。

## 签名

固定一个 keystore，**丢了就再也无法覆盖安装**，只能让用户卸载重装（记录会丢）。
备份到至少两个地方，别只留本机。

当前证书指纹（SHA-256）：

```
60A4:8974:2331:1074:A7F7:8924:AEBA:AF22:6F27:FCC9:1A60:BA39:FCF3:D2D6:4E77:7E80
```

想知道某个包是不是自己出的：

```
apksigner verify --print-certs 行测红卷.apk
```
